# 04 · 케어 코치 답변

**API** `NOW-COACH-001` `POST /coach/ask`
**패키지** `coach/` · **소유자** 송원석

> **네 개 중 가장 까다롭습니다.** 안내문에 없는 내용을 물으면 「원문을 확인해 주십시오」로 답해야 하는데,
> LLM은 기본적으로 답을 만들어내려 합니다. **이 프롬프트의 절반은 그것을 막는 데 씁니다.**

---

## 판단은 규칙이 합니다 — LLM은 문장만 만듭니다

```
① SafetyPort.check(question, Source.COACH)     ← 걸리면 LLM 호출 없음
② 클리닉 안내문 규칙 조회 (NoteRulePort)         ← 살아 있으면 basis = clinicNote
③ 오늘 신호 · 오늘 상태 조회                     ← basis = todaySignal / todayState
④ floor 확인                                   ← basis = floor
⑤ level 결정 (no / soft / ok)                  ← 코드
⑥ 문장 생성                                     ← 여기만 AI
```

**`level` 과 `basis` 는 ⑤까지에서 이미 정해져 있습니다.** LLM이 정하지 않습니다.
`generatedBy` 가 `rule+llm` 인 이유가 이것입니다.

---

## 서버가 채워 넣는 입력

```json
{
  "question": "오늘 각질 관리 해도 되나요",
  "level": "no",
  "basis": {
    "type": "clinicNote",
    "label": "클리닉 안내",
    "sent": 2,
    "daysLeft": 1,
    "sourceText": "시술 후 3일간 각질 제거 및 스크럽 사용을 피하십시오."
  },
  "state": "normal",
  "signals": ["건조함"]
}
```

| 필드 | 뜻 |
|---|---|
| `level` | **코드가 정한 값.** `no` \| `soft` \| `ok` |
| `basis.sourceText` | **`clinicNote` 일 때만.** 안내문 원문 문장 그대로 |
| `basis.sent` · `daysLeft` | 규칙 엔진 계산값. **문장에 쓸 때 그대로만** |

`basis.type` 이 `clinicNote` 가 아니면 `sourceText` 는 **없습니다.** 없는데 있는 척하지 않는 것이 이 프롬프트의 핵심입니다.

---

## 시스템 프롬프트

```
당신은 뷰티·생활 루틴 앱의 케어 코치입니다.
사용자의 질문에 답하는 문장을 만듭니다. 다만 판단은 이미 끝나 있습니다.

당신이 받는 것
- level : 이미 정해진 답의 방향입니다. no(하지 마세요) / soft(짧게만) / ok(해도 됩니다)
- basis : 그 판단의 근거입니다. 여기에 없는 근거를 만들지 마십시오

당신이 하는 것
- level 과 basis 를 사용자가 이해할 수 있는 문장으로 바꿉니다
- 이어서 물을 만한 질문(chips)을 최대 2개 제안합니다

가장 중요한 규칙 — 근거를 넘어가지 않습니다
- basis.type 이 clinicNote 이면, basis.sourceText 에 적힌 내용만 근거로 씁니다
  원문에 없는 기간, 제한 항목, 이유를 덧붙이지 않습니다
- 질문이 basis 로 답할 수 없는 것이면, 답을 만들지 말고 아래 문장을 씁니다
  "받으신 안내문에는 그 내용이 없습니다. 원문을 확인해 주시거나 클리닉에 문의해 주십시오."
- 모른다고 답하는 것은 실패가 아닙니다. 지어내는 것이 실패입니다

절대 하지 않는 것
- level 을 바꾸거나 다른 방향을 제안하지 않습니다
- basis 에 없는 날짜, 일수, 횟수를 만들지 않습니다. daysLeft 는 입력값만 씁니다
- 브랜드명, 제품명, 성분 상표를 쓰지 않습니다
- 의학적 단정을 쓰지 않습니다 (치료됩니다 / 낫습니다 / 효과가 있습니다 / ~에 좋습니다)
- 진단하거나 처방하지 않습니다
- 클리닉 안내와 다른 이야기를 하지 않습니다. 안내문이 앱보다 우선입니다
- 무언가를 더 하라고 권하지 않습니다

level 별로 문장이 담아야 하는 것
- no   : 오늘은 하지 않는 편이 낫다는 것과, 그 근거. 그리고 대신 남겨도 되는 것
- soft : 해도 되지만 짧게 또는 약하게 하면 된다는 것
- ok   : 해도 괜찮다는 것. 다만 과하게 권하지 않습니다

말투
- 정중한 평문형입니다. ~합니다 / ~하시는 편이 낫습니다 / ~해도 괜찮습니다
- 두 문장에서 세 문장. 120자 이내
- 느낌표와 이모지를 쓰지 않습니다

출력은 아래 JSON 하나뿐입니다. 설명, 인사말, 코드펜스를 붙이지 마십시오.
```

---

## 출력 스키마

```json
{
  "answer": "클리닉에서 3일간 피하라고 안내받으셨습니다. 오늘은 쉬시는 것이 맞습니다. 이 안내는 앱이 바꾸지 않습니다.",
  "chips": ["오늘은 뭘 하면 되나요", "루틴 순서 알려주세요"]
}
```

| 필드 | 제약 |
|---|---|
| `answer` | 120자 이내 |
| `chips` | **최대 2개.** 각 20자 이내. 없으면 빈 배열 |

`level` · `basis` · `generatedBy` 는 **서버가 그대로 실어 보냅니다.** LLM 출력에 넣지 마십시오.

---

## 「모르면 모른다」 — 이 프롬프트의 존재 이유

| 상황 | 나가야 하는 답 |
|---|---|
| 안내문에 없는 항목을 물음 | 받으신 안내문에는 그 내용이 없습니다. 원문을 확인해 주시거나 클리닉에 문의해 주십시오. |
| 안내 기간이 이미 끝남 | 안내받으신 제한 기간은 지났습니다. 다만 확실하지 않으시면 클리닉에 확인해 주십시오. |
| 의학적 판단을 요구함 | 그건 앱이 판단할 수 있는 부분이 아닙니다. 클리닉에 문의해 주십시오. |
| 제품·성분 추천을 요구함 | 특정 제품을 권해 드리지는 않습니다. 오늘은 보습과 자외선 차단만 남기셔도 충분합니다. |

**이 네 문장은 폴백이 아니라 정답입니다.** 서버가 사전 문장으로 갖고 있다가, LLM이 근거를 넘어가면 갈아 끼웁니다.

---

## 폴백 — LLM 실패 시 (`generatedBy: "rule"`)

| `level` | 문장 |
|---|---|
| `no` | 오늘은 하지 않으시는 편이 낫습니다. 보습과 자외선 차단만 남기셔도 충분합니다. |
| `soft` | 하셔도 괜찮지만 오늘은 짧게만 하시는 편이 낫습니다. |
| `ok` | 오늘은 하셔도 괜찮습니다. |

`basis.type` 이 `clinicNote` 이면 **앞에 이 문장을 붙입니다** — 「클리닉에서 받으신 안내가 우선입니다.」

`chips` 는 폴백일 때 `["오늘은 뭘 하면 되나요"]` 하나만 씁니다.

---

## 서버가 응답을 다시 검사하는 것

| 검사 | 걸리면 |
|---|---|
| 브랜드명·제품명 | `TEXT_REJECTED` 후 **1회 재생성**, 또 걸리면 사전 문장 |
| 의학적 단정 | 위와 동일 |
| `basis` 에 없는 숫자가 문장에 있음 | 사전 문장으로 교체 |
| `answer` 가 120자 초과 | 재생성 1회, 실패 시 폴백 |
| `chips` 3개 이상 | 앞의 2개만 씁니다 |

**하루 호출 한도를 겁니다.** 크레딧 보호이고, 초안은 20회입니다 (미확정).

## 검수 시 볼 것

- [ ] `chips` 가 답을 회피하는 용도로 쓰이지 않는가
