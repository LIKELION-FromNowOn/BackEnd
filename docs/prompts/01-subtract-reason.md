# 01 · 판정 근거 문장 생성

**API** `NOW-SUB-001` `POST /subtract/evaluate` — 처리 순서 **⑥단계에서만** 호출
**패키지** `subtract/` · **소유자** 송원석

> **⑥ 앞뒤는 전부 코드입니다.** ①~⑤에서 후보를 최대한 줄인 뒤에 넘기고, ⑦에서 다시 검사합니다.
> **LLM에 넘기는 항목이 8개를 넘으면 나눠서 부르지 말고 그대로 한 번에 부릅니다.** 한 사람의 판정은 한 호출로 끝나야 합니다.

---

## 서버가 채워 넣는 입력

```json
{
  "state": "normal",
  "capacity": 70,
  "judgeStrength": "medium",
  "signals": ["건조함", "당김"],
  "items": [
    {
      "itemId": "et_003",
      "name": "물 2L 마시기",
      "category": "life",
      "frequency": "daily",
      "floor": "essential",
      "evidenceLevel": "high",
      "load": 1.8,
      "score": 0.42,
      "verdict": "simplify"
    }
  ]
}
```

| 필드 | 누가 정하는가 |
|---|---|
| `verdict` | **코드입니다.** 점수 계산으로 이미 정해져 있습니다 |
| `load` · `score` | 코드 |
| `reason` | **LLM이 만드는 유일한 값** |

**`verdict` 를 바꾸라고 요청하지 마십시오.** LLM은 이미 정해진 판정에 문장을 붙이기만 합니다.

---

## 시스템 프롬프트

```
당신은 뷰티·생활 루틴을 「덜어내는」 것을 돕는 앱의 문장 작성기입니다.

당신의 역할은 단 하나입니다. 이미 정해진 판정(verdict)에 대해,
사용자가 납득할 수 있는 짧은 근거 문장(reason)을 만드는 것입니다.

절대 하지 않는 것
- verdict 를 바꾸거나 다른 값을 제안하지 않습니다
- 입력에 없는 항목을 만들지 않습니다
- 숫자를 새로 만들지 않습니다. load, score, daysLeft 는 입력값만 씁니다
- 브랜드명, 제품명, 성분 상표를 쓰지 않습니다
- 의학적 단정을 쓰지 않습니다 (치료됩니다 / 낫습니다 / 효과가 있습니다 / ~에 좋습니다)
- 사용자를 탓하는 문장을 쓰지 않습니다
- 무언가를 더 하라고 권하지 않습니다

판정별로 문장이 답해야 하는 것
- keep      : 왜 이것은 그대로 두는지
- simplify  : 무엇을 줄이는 것이 아니라 어떤 방식을 간단히 하는 것인지
- reduce    : 무엇을 얼마나 줄이는지
- skip      : 왜 오늘만 쉬어도 괜찮은지
- excluded  : 앱이 판단하지 않는 이유. 사용자에게 선택을 요구하지 않습니다

말투
- 정중한 평문형입니다. ~합니다 / ~해도 괜찮습니다 / ~하시는 편이 낫습니다
- 한 문장에서 두 문장까지. 40자 이내를 권장합니다
- 느낌표와 이모지를 쓰지 않습니다

simplify 를 쓸 때 특히 주의하십시오.
「덜 하라」가 아니라 「하되 방식을 간단히 하라」입니다.
예: 물 2L 마시기 → "2L는 그대로 두고, 세는 것만 그만둡니다."

출력은 아래 JSON 하나뿐입니다. 설명, 인사말, 코드펜스를 붙이지 마십시오.
```

---

## 출력 스키마

```json
{
  "reasons": [
    { "itemId": "et_003", "reason": "2L는 그대로 두고 세는 것만 그만둡니다." }
  ]
}
```

| 규칙 | 내용 |
|---|---|
| 개수 | **입력 `items` 와 정확히 같은 수, 같은 `itemId`** |
| 길이 | 각 `reason` 60자 이내 |
| 순서 | 입력 순서를 지킵니다 |

**`itemId` 가 하나라도 어긋나면 그 항목만 폴백 문장으로 대체합니다.** 전체를 버리지 마십시오.

---

## 폴백 문장 — LLM 실패 시 그대로 씁니다

| 판정 | 문장 |
|---|---|
| `keep` | 오늘은 이대로 두어도 괜찮습니다. |
| `simplify` | 그만두는 것이 아니라, 오늘은 방식만 간단히 합니다. |
| `reduce` | 오늘은 평소보다 조금만 줄여 봅니다. |
| `skip` | 오늘 하루 쉬어도 흐름은 끊기지 않습니다. |
| `excluded` (`floor`) | 이 항목은 앱이 판단하지 않습니다. |
| `excluded` (`clinicNote`) | 클리닉에서 받으신 안내가 우선입니다. 앱이 바꾸지 않습니다. |

**폴백을 쓴 경우 응답의 `generatedBy` 를 `fallback` 으로 채웁니다.**

## ⑦단계에서 서버가 다시 검사하는 것

이 프롬프트가 잘 돌아도 **⑦은 반드시 돕니다.**

| # | 검사 | 걸리면 |
|---|---|---|
| 6 | 근거 문장에 브랜드명·제품명이 있는가 | 위 폴백 문장으로 교체 |
| 7 | 근거 문장에 의학적 단정이 있는가 | 위 폴백 문장으로 교체 |

의학적 단정 판정은 **금지어 목록 대조**로 시작합니다 (`치료` `완치` `낫습니다` `효과가 있습니다` `좋습니다` `개선됩니다` `예방합니다`).
목록은 `safety/` 가 관리하며, 걸린 건수를 로그로 남깁니다.

---

## 검수 시 볼 것

- [ ] `simplify` 문장이 「줄이라」는 뜻으로 읽히지 않는가
- [ ] `excluded` 문장이 사용자에게 선택을 요구하지 않는가
- [ ] `floor: essential` 항목에 「안 해도 된다」로 읽히는 문장이 없는가
- [ ] 60자를 넘는 문장이 없는가
