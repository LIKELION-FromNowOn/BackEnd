**작성 송원석 · 2026-08-15 초안**
**이 폴더의 파일은 코드가 아니라 산출물입니다.** 호출은 각 패키지 소유자가 합니다.

| # | 파일 | API | API 소유자 | 프롬프트 소유자 |
|---|---|---|---|---|
| 1 | `01-subtract-reason.md` | `NOW-SUB-001` `POST /subtract/evaluate` | 송원석 | 송원석 |
| 2 | `02-today-action.md` | `NOW-TODAY-001` `GET /today` | **김민정** | 송원석 |
| 3 | `03-item-interpret.md` | `NOW-ITEM-003` `POST /me/items/custom` | **이철희** | 송원석 |
| 4 | `04-coach-answer.md` | `NOW-COACH-001` `POST /coach/ask` | 송원석 | 송원석 |

**2·3번은 API 소유자와 프롬프트 소유자가 다릅니다.** 그래서 문자열을 이 파일로 넘기고, 호출 코드는 각자 자기 패키지 안에 씁니다.
**LLM 클라이언트는 `common/llm/` 하나입니다.** 재시도·타임아웃·폴백을 세 벌 만들지 마십시오.

## 절대 규칙 다섯

| # | 규칙 | 이유 |
|---|---|---|
| 1 | **판정·수치는 코드가 정합니다. LLM은 문장만 만듭니다** | LLM이 `verdict` 를 정하면 하한선 위반이 매번 나옵니다 |
| 2 | **출력은 JSON 하나뿐입니다** | 자유 문장으로 받으면 파싱이 깨집니다. 설명·인사말·코드펜스 금지 |
| 3 | **모르면 지어내지 않습니다** | 근거에 없는 내용을 물으면 「원문을 확인해 주십시오」로 넘깁니다 |
| 4 | **호출이 실패해도 빈 결과를 반환하지 않습니다** | 각 파일의 폴백 문장을 씁니다. 화면이 비면 안 됩니다 |
| 5 | **응답은 서버가 한 번 더 검사합니다** | 브랜드명·의학적 단정이 걸리면 사전 문장으로 갈아 끼웁니다 |

## 말투

**정중한 평문형입니다.**

| 쓰는 것 | 쓰지 않는 것 |
|---|---|
| ~합니다 · ~해도 괜찮습니다 · ~하시는 편이 낫습니다 | ~하세요 · ~해요 · ~하자 |
| 사용자를 「~님」 또는 생략 | 「고객님」 · 「당신」 |
| 담백한 서술 | 느낌표 · 이모지 · 「!」 「^^」 |

**한 문장에서 두 문장까지.** 길면 화면에서 잘립니다.

---

## 금지 표현 — 네 프롬프트 공통

| 종류 | 예 | 대신 |
|---|---|---|
| **브랜드명 · 제품명** | 특정 회사·제품·성분 상표 | 「보습제」 「자외선 차단제」 같은 일반명 |
| **의학적 단정** | 「치료됩니다」 「낫습니다」 「효과가 있습니다」 「~에 좋습니다」 | 「~하는 분이 많습니다」 「~하시는 편이 낫습니다」 |
| **진단 · 처방** | 「~염입니다」 「~을 드시면 됩니다」 | 「클리닉에 확인해 보시는 편이 낫습니다」 |
| **단정적 수치** | 「3일이면 낫습니다」 | 규칙 엔진이 준 `daysLeft` 만 그대로 |
| **죄책감 유발** | 「지금까지 잘못하고 계셨습니다」 「관리를 안 하셨네요」 | 판단하지 않고 사실만 |

> **이 앱의 핵심은 「덜어내기」입니다.** 더 하라고 권하는 문장은 그 자체로 어긋납니다.

## 위기 신호는 프롬프트가 아니라 코드입니다

자유 입력 다섯 경로(`ITEM_CUSTOM` · `SIGNAL_CUSTOM` · `COACH` · `PLAN` · `NOTE`)는 **LLM에 보내기 전에** `SafetyPort.check()` 를 먼저 통과해야 합니다.
걸리면 **LLM을 아예 호출하지 않고** 상담 안내를 반환합니다. 프롬프트로 막으려 하지 마십시오.

## 호출 규약

```java
// common/llm/LlmClient.java
<T> T ask(String systemPrompt, String userPayloadJson, Class<T> responseType);
```

| 항목 | 값 |
|---|---|
| 타임아웃 | **10초** |
| 재시도 | **없음.** 형식 실패든 네트워크 실패든 재시도하지 않고 폴백으로 갑니다. **최악 대기를 10초로 고정하는 것이 목적입니다** |
| 추론 단계 | **`reasoning_effort: low`** — 자리마다 다르게 줄 수 있습니다 |
| 최악 대기 | **10초** (전에는 6초 + 재시도 6초 = 12초였습니다) |
| 실패하면 | **폴백 문장 사용 + `generatedBy` 를 `fallback` 으로** |
| 응답이 JSON이 아님 | 파싱 실패로 보고 위와 동일하게 처리 |

> **2026-08-20 개정.** 팀 OpenAI 키로 `gpt-5.6-luna` 를 9회 호출해 잰 값이 근거입니다.
>
> | `reasoning_effort` | 평균 | 최대 | 출력 토큰 | 추론 토큰 |
> |---|---|---|---|---|
> | `none` | 6.06초 | 6.86초 | 549 | **0** |
> | **`low`** | **6.38초** | **6.44초** | 604 | 61 |
> | `medium` | 6.45초 | 6.86초 | 634 | 82 |
>
> **세 단계 모두 6초를 넘었습니다.** 그대로 두면 매번 폴백으로 떨어져 AI 를 켜 놓고 안 쓰게 됩니다.
>
> **시간을 먹는 것은 추론이 아니라 출력량입니다** — `none` 은 추론 토큰이 0개인데도 6.06초입니다.
> 항목 8개에 1~2문장씩 만드느라 걸립니다. 그래서 `reasoning_effort` 를 `low` 로 두어도 대가가 0.39초뿐입니다.
>
> **재시도를 뺀 이유** — 타임아웃만 10초로 늘리면 최악이 20초가 됩니다. 시연에서 20초는 쓸 수 없습니다.
> 그리고 `response_format: {"type":"json_object"}` 로 JSON 을 API 수준에서 강제하므로,
> 재시도가 지키던 「형식 깨짐」이 이미 막혀 있습니다. **실측 9회 전부 파싱에 성공했습니다.**
>
> **다만 항목이 15개를 넘는 경우와 실서버 네트워크에서는 재지 않았습니다.**
> 근거 — `FromNowOn/DISCREPANCIES-0819.md` 회신 14-CC · 15

**`generatedBy` 필드를 항상 채우십시오.** 발표에서 「AI가 진짜 도는지」를 이 필드로 보여 줍니다.
