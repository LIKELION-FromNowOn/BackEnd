## 8/14 오전 — 「이철희에게 너무 몰려 있다」

### 1차 시도 — 축 단위로 전면 재설계 (되돌림)

이철희 님이 API 37건 중 **33건(89%)** 을 맡고 있었고 김민정 님은 **0건**이었습니다.
처음에는 「계정 / 데이터 / 판정」 세 축으로 **완전히 새로 그렸습니다** — 33건 → 11건.

**되돌렸습니다.** 이유는 사용자(PM)의 지적이 정확했기 때문입니다.

> 「이미 작업에 들어갔는데 처음부터 판을 새로 짜면 곤란하다. 철희 일이 100이면 30 정도만 나눠 달라.」

### 2차 — 건수 기준 30%

빼기 안전한 것만 골랐습니다 — 마스터 3 · 첫 발자국 1 · 기록 2 · 마이 1 → 김민정 / 덜어내기 2 · 안내문 원문 1 → 송원석.
**8/15 「인증·관리항목·상태 12건」 묶음은 손대지 않았습니다.**

### 3차 — 작업량 기준 30 / 35 / 35 (최종)

「단순히 수만 세지 말고 계산해 달라」는 요청으로 다시 재 보니, **건수 30% 를 뺐는데 작업량으로는 23%** 였습니다.
뺀 것이 대부분 가벼운 조회성이었기 때문입니다. 이철희 님은 여전히 **50.9%** 였습니다.

그래서 난이도를 네 등급으로 나눠 시간을 매기고 다시 나눴습니다.

| | 8/13 | 최종 |
|---|---|---|
| 이철희 | 56h · 66.7% | **25.5h · 30.2%** |
| 김민정 | 4.5h · 5.4% | **30h · 35.5%** |
| 송원석 | 23.5h · 28.0% | **29h · 34.3%** |

**날짜별로 보니 더 심각했습니다** — 조정 전 이철희 님은 8/15 에 16.5시간, 8/16 에 20시간이었습니다. 물리적으로 불가능한 값입니다.

## 8/14 오후 — 패키지 구조와 「겹치지 않게」

### 김민정 님의 질문에서 시작

> 「기능별로 파일을 개개인이 만들 텐데, 유저 파일을 만든다 하면 유저 컨트롤러·유저 서비스를 만들 텐데 겹치지 않아야 할 것 같아요.」
> 「여러 기능에 유저가 쓰일 텐데, 그게 안 겹치게 짜 주실 수 있나요.」

**정확한 지적이었고, 이 질문이 패키지 설계 전체를 만들었습니다.**

| 답 | 내용 |
|---|---|
| 구조 | **기능(도메인)별 패키지.** 계층별이면 셋이 매일 같은 세 폴더를 건드립니다 |
| 유저 | **`User` 를 넘기지 않고 `Long userId` 만.** `@ManyToOne User` 를 쓰면 14개 패키지가 한 덩어리가 됩니다<br>▸ **8/18 정정 — 타입은 `Long` 이 아니라 `String` 입니다.** 「넘기지 않는다」는 원칙은 그대로입니다 |

### 이어진 질문 — 「같은 이름 파일을 둘이 만들면?」

> 「유저 서비스 파일이 있는데 또 다른 개발진이 유저 서비스 파일을 또 만들면 충돌이 분명하게 나니까요.」

**맞지만 터지는 곳이 다릅니다.** 경로가 달라 Git 충돌은 안 나고, **스프링 부팅이 실패**합니다.

```
ConflictingBeanDefinitionException: bean name 'userService' ... conflicts
```

→ **클래스 이름에 패키지 접두어를 붙이는 규칙**이 여기서 나왔습니다. `User*` 는 `auth/` 예약어.

### 발견한 실제 충돌 한 곳

`GET /me`(이철희)와 `PATCH /me`(김민정)가 **같은 `users` 테이블**을 쓰고 있었습니다. 김민정 님이 우려한 상황이 실제로 있었던 것입니다.
→ `PATCH /me` 를 `auth/` 로 합쳤습니다.

## 8/14 저녁 — 트래픽 설계, 그리고 정정

처음에는 응답을 최대한 얇게 만드는 규칙 일곱 개를 만들었습니다. 하루 52KB → 8KB.

**그런데 팀 목표가 「프론트·디자인 포함 2MB」라는 것을 듣고 다시 재 보니, API JSON 은 예산의 0.5% 였습니다.**
44KB 를 아낀 것은 2MB 의 2% 입니다. **폰트 하나가 API 전체의 백 배**입니다.

| 조치 | 규칙 |
|---|---|
| **폐기** | 「이름 대신 id」 — 2KB 아끼려고 예외 분기·빈칸 실패 모드를 감수할 이유가 없음 |
| **완화** | 홈 요약 · 화면당 호출 2회 상한 |
| **유지** | 캐시 헤더 · 목록 제한 · 폴링 금지 · N+1 금지 — **바이트가 아니라 요청 수·안정성 때문** |

그리고 한 곳은 **제가 너무 줄였다가 되살렸습니다** — 홈의 「사우나 5일 남음」을 개수로만 줄였는데, 그게 차별점을 첫 화면에서 보여주는 문장이었습니다.

## 8/14 · 황인서 님의 확인 요청

프론트에서 명세서와 시안을 대조해 **아무도 못 본 두 가지**를 찾아 왔습니다.

| # | 무엇 | 왜 중요한가 |
|---|---|---|
| 1 | **관리 항목 화면에 빈도 설정 UI 가 없음** | `load = base + FQL[frequency]`. **빈도가 없으면 판정 점수 전체가 틀어집니다.** UX 문제가 아니라 엔진 문제 |
| 2 | **컨디션 선택지에 「모르겠다」가 없음** | 정도가 아니라 **답을 안 하는 선택지**. 여력값 60 이 따로 있습니다 |

그리고 `excluded` 라는 이름이 「화면에서 숨김」으로 읽힌다고 지적했습니다.
→ **이름은 유지하고 정의를 명세서에 박기로** 했습니다. 다섯 곳에 박혀 있고 `excludedBy` 와 짝이라 동결 6일 전에 바꿀 자리가 아닙니다.

## 마지막에 발견한 제 오류 — AI 호출은 2곳이 아니라 4곳

「시스템 아키텍처」에 **「LLM 호출 지점은 2곳뿐」** 이라고 적어 두었는데,
노션 「프롬프트 4종 초안」을 열어 보니 **네 곳**이었습니다.

| # | 어디 | API | API 소유자 | 프롬프트 소유자 |
|---|---|---|---|---|
| 1 | 판정 근거 문장 생성 | `NOW-SUB-001` | 송원석 | 송원석 |
| 2 | **오늘의 행동 생성** | `NOW-TODAY-001` | **김민정** | 송원석 |
| 3 | **직접 입력 텍스트 해석** | `NOW-ITEM-003` | **이철희** | 송원석 |
| 4 | 케어 코치 답변 | `NOW-COACH-001` | 송원석 | 송원석 |

**2·3번은 API 소유자와 프롬프트 소유자가 다릅니다.** 「폴더 하나에 사람 하나」와 충돌합니다.

→ **프롬프트는 코드가 아니라 산출물로 넘깁니다.** 송원석이 문자열·폴백·금지 표현을 파일로 주고, 호출은 각 패키지 소유자가 합니다. LLM 클라이언트는 `common/llm/` 하나.
